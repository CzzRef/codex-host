# codexhost

`codexhost` 讨论如何让多个 Agent Harness 在 Codex Desktop 外壳中以独立会话运行。本术语表用于避免把 UI、Harness、Model 和账号路由混为一谈。

## Language

**codexhost**:
一个让非 Codex Harness 能以会话形式运行在 Codex Desktop 外壳中的独立第三方产品。
_Avoid_: Codex Host、codex-host、Codex++

**Codex Desktop**:
用户看到并操作的官方桌面外壳，包括项目、会话、输入框和交互渲染。
_Avoid_: Harness 内核、Codex Core

**Agent**:
Harness 在用户界面中的名称。
_Avoid_: Model、Provider

**Harness**:
拥有 Agent Loop、上下文组织、工具系统、权限交互和原生会话状态的执行主体，例如官方 Codex、Claude Code 或 Pi。
_Avoid_: Model、Model Provider、Runtime Core

**Model**:
被 Harness 调用以完成推理生成的模型，例如 GPT、Claude、Gemini 或本地模型。
_Avoid_: Harness、Agent

**Provider**:
承载模型请求并提供 Endpoint、Wire Protocol 与服务能力的后端。Provider 可能约束可用认证和计费方式，但不等同于当前使用的账号或实际额度来源。
_Avoid_: Harness、Model、Account

**Account / Authentication**:
用于访问 Provider 或 Harness 的用户身份与认证方式，例如 Codex OAuth、Anthropic OAuth 或 API Key。账号说明“以谁的凭据访问”，不等同于请求后端或最终扣费来源。
_Avoid_: Provider、实际额度来源

**Thread**:
归属于一个且仅一个 Harness 的用户会话。Harness 在 Thread 内固定，但 Model 可以在不同 Turn 之间切换。
_Avoid_: 跨 Agent 流水线、共享原生 Session

**Turn**:
Thread 内由一次用户输入触发，并以完成、失败或取消结束的一次 Harness 执行。
_Avoid_: Thread、单条 Message

**Fork**:
从现有 Thread 的当前末尾或某个历史位置派生一个新的独立 Thread。Fork 只分叉会话上下文；派生 Thread 必须继承来源 Thread 的 Harness，并继续读取同一项目的当前文件状态。具体复制哪些 Native Session 上下文状态由 Harness 能力和产品保真承诺决定。
_Avoid_: 切换 Agent、跨 Harness 迁移、原 Thread 原地改写、文件回滚、文件快照、自动 Worktree

**Native Session**:
由所选 Harness 自己维护的原生会话与执行状态。
_Avoid_: Codex Thread

**Native Turn Ref**:
由具体 Harness Adapter 提供的稳定、opaque 原生 Turn 身份，用于在实时执行和重复读取 Native Session 历史时识别同一个逻辑 Turn。它不表示 Turn 可 Fork，也不包含消息正文。
_Avoid_: Host Turn ID、Native Checkpoint、Turn Anchor

**Native Checkpoint**:
由具体 Harness 标识的可 Fork 会话历史位置，例如 Claude Code 的 Assistant Message UUID 或 Pi 的 Session Entry ID。它不是 Turn 身份、文件快照或独立 Transcript。
_Avoid_: Native Turn Ref、Native Session、Codex Turn、文件 Checkpoint

**Turn Anchor**:
CodexHost 保存的 `Host Turn ID → Native Checkpoint ID` 定位元数据，用于 Fork 等精确会话操作。它不包含消息正文，不构成第二份会话事实源。
_Avoid_: Transcript 投影、Native Session

**Adapter**:
连接某个具体 Harness 的适配层，负责启动或恢复 Native Session，并把该 Harness 的结构化输入、事件和交互转换为 `codexhost` 的稳定内部语义。
_Avoid_: Protocol Facade、Model Provider

**Host Interaction**:
需要用户响应后才能继续的双向交互，例如审批或 Agent 提问。它包含跨 Codex UI 与原生 Harness 回调所需的关联标识。
_Avoid_: 单向事件、普通消息

**Permission Mode**:
由当前 Harness 定义的会话级权限基线，决定工具调用默认被自动允许、询问还是拒绝。不同 Harness 的模式数量和语义不同，不能把 Codex UI 的权限档位直接当作 Claude Code/Pi 的原生模式。
_Avoid_: 单次 Approval Request、Sandbox

**Approval Request**:
Harness 在实际执行某次工具调用前发起、需要用户作出允许或拒绝决策的运行时交互。CodexHost 可以把它转换成 Codex UI 可表达的 Host Interaction，但不因此拥有原生权限策略。
_Avoid_: Permission Mode、Sandbox

**核心工作区（Core Workspace）**:
Thread cwd 所在的 Git 根（inspect 快照中的 `primary` 行）。对话没有改动文件时它待在轮次头第一行（提示词钉住时让位），有改动文件时回到第二行第一枚 chip；两种情形都显示。
_Avoid_: 主仓库（可能是 linked worktree）、项目根

**涉及仓库（Repository Touched）**:
对话改动文件所落在的其他 Git 根：同 checkout 家族的 submodule / 兄弟 worktree / additional 根，或经 `extraPaths` 解析出的 `external` 根。只有非零行改动的涉及仓库才出现在轮次头第二行。
_Avoid_: 工作区列表全量、依赖仓库

**轮次头（Turn Header）**:
codexhost 钉在 transcript 顶部、Desktop 标题栏之下的不透明面层。第一行是「第 N/M 轮」（有 Host `turnIds` 时按 Host 轮次列表计数，DOM 窗口只是兜底）、当前轮提示词（气泡滚出 transcript 视口后才出现）与 编辑 / 回滚 / Redo；第二行只在对话有改动文件时存在，放涉及仓库与文件披露，其余时候核心工作区 chip 走第一行、整条只有一行。挂在 `document.body` 上，对齐 Composer 列，并在内容列上预留自身高度。
_Avoid_: 状态栏、悬浮动作簇、Desktop 自己的标题栏

**当前轮（Current Turn）**:
轮次头描述的那一轮：按视口推导——顶缘已越过「探针线」（轮次头底边下方固定一段，必须大于轮次头自己滚动时留的间隙）的最后一个 `[data-turn-key]`；transcript 末尾可见时是最后一轮；都没有时是第一轮。编辑 / 回滚 / Redo 作用于它，而不是点击选中的轮次。
_Avoid_: 选中轮次、最后一轮（除非末尾在视口内）、正在运行的 Turn
